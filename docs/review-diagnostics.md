# 质检保存诊断

## 记录与口径

质检保存仍使用原有共享盘锁和原子 rename。诊断事件不进入业务 JSON；新标记仅增加可选 operation_id，用于丢失响应后的严格核对。旧客户端、旧记录和缺失快照继续兼容，缺失值不补零，也不推断人为原因。

正常 PUT 附带客户端构建版本、页面会话 ID、操作 ID、快照状态和当前 Episode 的有界计时摘要（启停次数、就绪状态、sessionStorage 异常）。没有逐帧采集或新心跳。服务端记录 received/completed 两条事件，包含请求 ID、服务端版本、匿名数据集/人员标识，以及锁等待、读取、写入、提交、清理耗时。failed_phase 保留失败阶段；committed 表示 rename 完成，不代表客户端收到响应。

时间戳复用项目 reviewTimestamp（UTC+8），耗时用 performance.now，客户端和服务端独立计时。诊断不改变覆盖率、Episode 内容时长和打标时快照的既有定义。计时尚未初始化或无有效内容时长时保持缺失并记录原因，合法的零停留值保持为零。

## 资源与配置

- 默认启用；设置 REVIEW_DIAGNOSTICS_ENABLED=0 并重启可关闭服务端文件记录。测试默认禁用。
- 默认目录：服务进程工作目录下 .xense-diagnostics/reviews。REVIEW_DIAGNOSTICS_DIR 可指定本机日志目录，不应设到数据集或慢速共享盘。
- 等待队列最多 512 条，单条最多 4 KiB，单批最多 32 条，每 1 秒异步刷新；在途批次另计。磁盘阻塞或不可写不等待业务保存；溢出丢弃并计数，不无界积压或重试。
- 每文件最多 2 MiB，按进程及随机 ID 分文件；初始化及轮转时清理本日志命名空间，保留最新 20 个文件、最多 7 天。单实例约 40 MiB，多实例同时轮转为尽力上限，推荐每服务独立目录并由宿主设配额。
- 新目录/文件权限为 0700/0600。日志不含姓名、原始路径、任意诊断字段、请求正文或原始异常消息。匿名标识用进程内随机密钥生成，跨重启不保持一致。
- GET /api/review-diagnostics 返回当前进程的队列、written/dropped/write_failures/high_water 及客户端结果限流计数，不返回日志或路径。PUT 响应头提供 X-Review-Request-Id、X-Review-Build。
- 客户端版本在构建/开发服务启动时确定，优先 REVIEW_BUILD_ID、VERCEL_GIT_COMMIT_SHA、GITHUB_SHA，最后回退 Git 短 SHA；有未提交改动时附加 -dirty，无 Git 时为 unknown。切换版本后需重新构建/重启及刷新旧页面。

请求体限制为保存 8 KiB、客户端异常上报 2 KiB；流式读取最长 10 秒，覆盖无 Content-Length 的慢速上传。超时返回 408，断开返回 499，超限返回 413；读取取消不等待底层取消处理器，失败后不进入业务写入。正常读取响应必须完整校验人员列表、角色、数据集标识及记录，再一次性更新页面状态；异常响应保留原页面数据并显示错误。

## 超时核对

证据核对使用同一范围下的 GET /reviews?operation_id=...&verify=1，只读取并校验业务记录和该范围的回执，不依赖人员配置；缺少操作 ID 返回 400。普通刷新仍完整校验人员配置。独立核对不会清除人员配置错误，也不会据此开放不合法的新写入。服务端在范围确认后先登记操作回执，再校验人员；人员被移除或配置损坏造成的失败也能以终态回执核对。业务文件损坏仍报错，不返回伪造的空记录。

PUT 的 15 秒期限覆盖响应头和正文，正常成功响应还必须符合请求的标记/撤销状态。超时、断网、408/499、5xx、正文错误或响应状态不一致时，只做一次 5 秒期限 GET，不重放写请求。人员、Episode 与 operation_id 一致的持久标记，或同一操作的成功回执，才能确认提交；旧标记、其他操作和取消后记录不存在，都不能单独证明本次成功。

无法确认时显示“保存结果尚未确认”和操作编号，本页暂时禁止重复提交该标记。“刷新核对”只核对当前标记，不清除其他未知操作；处理中或没有证据时保持阻塞，确认成功后解除，服务端请求报错但已结束时展示当前数据及错误、允许用户核对后再次操作。后台刷新不静默解除提示，其他 Episode 的队列继续执行。普通读取也有 10 秒期限并支持取消，挂起的自动刷新不会永久挡住手动核对。待核对操作按浏览目录、数据集、人员及 Episode 隔离，除本页内存保护外，在 sessionStorage 可用时保留已发送操作的关联信息；返回页面或整页刷新后恢复保护，只读回核对，不重发 PUT。每个标签页最多保留 256 项，满额后拒绝新增，不淘汰未确认操作。页面离开时取消尚未发送的排队操作并明确提示；这些操作不写入恢复记录，也不会在页面返回后迟到发送。

浏览器存储不可用时保留本页内存保护并显示警告，不能承诺整页重载后的恢复；读取失败时不覆盖原恢复数据。本地恢复数据损坏时阻止新提交并保留证据，需先人工核对服务端操作再恢复，不能通过清空数据自动假定失败。恢复信息只用于核对，不含诊断摘要，不替代跨标签页/跨设备的服务端持久幂等协议。

页面另列出当前范围内其他人员、其他 Episode 的待核对操作，人员已从配置中移除、人员列表为空或当前浏览其他 Episode 时仍能逐项核对。每次只处理选定操作；成功和终态失败都显示人员及 Episode 的结果，处理中、证据缺失或核对读取失败继续保留保护，不重发 PUT，不自动删除其他待核对项。

操作回执与诊断日志独立，不增加逐帧请求。处理中的状态保存在服务进程内：每进程最多 1024 项，终态缓存最多保留 10 分钟（容量紧张可提前淘汰），处理中项不按时间误判为已完成；全部容量均为处理中项时不新增缓存回执，业务仍继续，状态接口的 operations.unavailable 计数增加。

终态证据另随每个数据集的 operation_receipts 保存到质检集合 JSON，与打标或撤销共用写锁和同一次原子替换。每个质检集合总计最多保留 4096 条终态，容量压力下优先保留当前数据集证据，按文件中数据集顺序淘汰其他数据集的旧终态（不保证跨数据集时间顺序），不修改检查记录或业务时间，不把处理中状态写入磁盘；只读核对优先使用磁盘终态，再读取进程缓存。请求被拒绝时在存储可写的前提下尽力保存失败证据，不覆盖已提交的成功证据、不改已有检查记录和检查时间。没有实际状态变化的新操作也保存独立证据；保留证据期间相同操作再次到达则不重复写入。读取和写锁内均校验操作 ID、人员、Episode、动作、来源及快照，保留证据期间旧撤销不能重放并删除后来的新标记。旧版质检文件不含 operation_receipts 时仍可读取，不因只读访问而改写；损坏、重复或集合总量超限的终态证据会报错，不能静默丢弃后覆盖。

持久终态支持正常服务进程重启及同一共享存储上的跨实例核对，但不是无限历史的全局幂等服务。历史超出 4096 条被淘汰、旧版本没有终态证据、存储损坏/不可写或提交前进程退出时，证据不足仍保持未知，不凭空确认或自动重试；当前持久标记中的 operation_id 仍可辅助核对。所有写入实例须升级到支持本格式的版本，旧服务写入会丢弃其不认识的历史字段。未验证断电落盘或 NFS 跨主机网络分区保证，也没有添加 fsync 承诺。

停留快照只在当前 key 已初始化后写 sessionStorage，加载阶段不会用零覆盖旧访问的值。pagehide 暂停并保存，pageshow 恢复，避免页面缓存期间累计为观看时间；存储失败仍保留本页内存计时并记入异常摘要。

异常保存才额外 POST /api/review-diagnostics 尽力报告结果，2 秒超时、2 KiB 限制、每进程每分钟最多 120 次；正常保存不增加请求。页面关闭或断网仍可能没有客户端结果。日志异步写入，没有 fsync 或持久投递保证，进程骤停可能丢失队列，不能作为审计或备份；缺日志不证明事件未发生。未知保存的服务端任务可能仍在结束，核对不构成取消或自动重试承诺。

## 验证

bun run validate 检查类型、lint、格式和全量测试。故障测试覆盖旧请求、合法零值、缺快照、无效诊断、并发/幂等、损坏业务文件、日志磁盘错误、饱和与恢复、轮转、丢响应后已提交/未知、取消操作和队列继续。

bun run test:review-save 使用独立 Chromium 测试实际 React Provider 和计时 hook，覆盖就绪前恢复、页面隐藏/返回、正常保存、两个未知操作独立核对、处理中阻塞、终态报错后显式重试、撤销丢响应、回执缺失与跨范围导航后的迟到响应。需要 Chrome/Chromium（可通过 CHROME_BIN 指定），临时目录和浏览器进程在结束时清理。

bun run test:review-production 对已构建的生产包启动独立 Node 服务（NODE_BIN 可指定版本），仅写自动清理的临时夹具。覆盖打标/撤销、操作冲突、双进程丢响应读回、真实未完成上传的 408、服务重启及诊断目录不可写。REVIEW_TEST_DATA_PARENT 可指定有写权限的测试父目录：脚本只创建随机命名的 .xense-review-validation-\* 独立子目录并自动清理，诊断日志始终使用本地临时目录，不修改既有数据集。已在当前 /mnt/datasets 的 NFS4 挂载验证双 Node 进程并发保存及原子提交，不能由此推断跨主机网络分区或断电落盘保证。浏览器恢复、播放、可用的 Python 测试、构建和生产故障检查已加入 Tests 工作流，类型、lint 和格式仍由独立工作流检查；仓库需启用 GitHub Actions 才会执行远端检查。

bun scripts/benchmark-review-diagnostics.ts 在自动清理的临时目录复测：3000 条记录、真实 flock 和全 JSON 重写，5 轮交替顺序、每模式 300 次保存。实测见 review-diagnostics-plan.md；本地夹具不代表共享盘、多进程或浏览器负载。
