# 质检保存诊断

## 记录与口径

质检保存仍使用原有共享盘锁和原子 rename。诊断事件不进入业务 JSON；新标记仅增加可选 operation_id，用于丢失响应后的严格核对。旧客户端、旧记录和缺失快照继续兼容，缺失值不补零，也不推断人为原因。

正常 PUT 附带客户端构建版本、页面会话 ID、操作 ID、快照状态和当前 Episode 的有界计时摘要（启停次数、就绪状态、sessionStorage 异常）。没有逐帧采集或新心跳。服务端记录 received/completed 两条事件，包含请求 ID、服务端版本、匿名数据集/人员标识，以及锁等待、读取、写入、提交、清理耗时。failed_phase 保留失败阶段；committed 表示 rename 完成，不代表客户端收到响应。

时间戳复用项目 reviewTimestamp（UTC+8），耗时用 performance.now，客户端和服务端独立计时。诊断不改变覆盖率、Episode 内容时长和打标时快照的既有定义。计时尚未初始化或无有效内容时长时保持缺失并记录原因，合法的零停留值保持为零。

## 资源与配置

- 默认启用；设置 REVIEW_DIAGNOSTICS_ENABLED=0 并重启可关闭服务端文件记录。测试默认禁用。
- 默认目录：服务进程工作目录下 .xense-diagnostics/reviews。REVIEW_DIAGNOSTICS_DIR 可指定本机日志目录，不应设到数据集或慢速共享盘。
- 等待队列最多 512 条，单条最多 4 KiB，单批最多 32 条，每 1 秒异步刷新；在途批次另计。磁盘阻塞或不可写不等待业务保存；溢出丢弃并计数，不无界积压或重试。
- 每文件最多 2 MiB，按进程及随机 ID 分文件；初始化及轮转时清理本日志命名空间，保留最新 20 个文件、最多 7 天。单实例约 40 MiB，多实例同时轮转为尽力上限，推荐每服务独立目录并由宿主设配额。
- 新目录/文件权限为 0700/0600。日志不含姓名、原始路径、任意诊断字段、请求正文或原始异常消息。匿名标识用进程内随机密钥生成，跨重启不保持一致。
- GET /api/review-diagnostics 返回当前进程的队列、written/dropped/write_failures/high_water 及客户端结果限流计数，不返回日志或路径。PUT 响应头提供 X-Review-Request-Id、X-Review-Build。
- 客户端版本在构建/开发服务启动时确定，优先 REVIEW_BUILD_ID、VERCEL_GIT_COMMIT_SHA、GITHUB_SHA，最后回退 Git 短 SHA；有未提交改动时附加 -dirty，无 Git 时为 unknown。切换版本后需重新构建/重启及刷新旧页面。

## 超时核对

PUT 的 15 秒期限覆盖响应头和正文。超时、断网、5xx 或无法解析响应时，只做一次 5 秒期限 GET，不重放写请求。只有人员、Episode 与 operation_id 一致才能确认本次标记已提交。旧标记、其他操作和取消后记录不存在，都不能证明本次成功。

无法确认时显示“保存结果尚未确认”和操作编号，本页暂时禁止重复提交该标记。“刷新核对”成功读取后，查看实际状态再决定下一步；后台刷新不静默解除提示。其他 Episode 的队列继续执行。

异常保存才额外 POST /api/review-diagnostics 尽力报告结果，2 秒超时、2 KiB 限制、每进程每分钟最多 120 次；正常保存不增加请求。页面关闭或断网仍可能没有客户端结果。日志异步写入，没有 fsync 或持久投递保证，进程骤停可能丢失队列，不能作为审计或备份；缺日志不证明事件未发生。未知保存的服务端任务可能仍在结束，核对不构成取消或自动重试承诺。

## 验证

bun run validate 检查类型、lint、格式和全量测试。故障测试覆盖旧请求、合法零值、缺快照、无效诊断、并发/幂等、损坏业务文件、日志磁盘错误、饱和与恢复、轮转、丢响应后已提交/未知、取消操作和队列继续。

bun scripts/benchmark-review-diagnostics.ts 在自动清理的临时目录复测：3000 条记录、真实 flock 和全 JSON 重写，5 轮交替顺序、每模式 300 次保存。实测见 review-diagnostics-plan.md；本地夹具不代表共享盘、多进程或浏览器负载。
